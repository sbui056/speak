02 · Session states

Every dictation follows the same seven states

One state machine owns the session. A press during a busy state is ignored, and every path ends back at idle with the mic closed. The last two boxes are how a session ends, not states of their own.

03 · Delivery

Paste only when it's safe, otherwise copy

The checks run in this order, immediately before the paste. The first failure copies the text and tells you exactly why, so your words are never lost.

  1. 0Is there any text? Empty after trimming.nothing · “Didn't catch that”
  2. 1Is Accessibility granted? Checked fresh before every paste.copy · Accessibility not granted
  3. 2Is secure input on? Password fields, secure terminals.copy · Secure input is on
  4. 3Is it still the same app? Compared by process ID captured at key press.copy · App changed
  5. 4Is a text field focused? Only when the system can answer reliably.copy · No text field focused
  6. 5Is it still the same field? Focus moved since you pressed the key.copy · Focus moved
  7. 6Are your modifier keys released? Otherwise ⌘V would arrive as ⌘⌥V.copy · Release modifier keys
  8. 7All clear Save the clipboard, paste, then restore it unless you copied something new.paste at cursor
04 · Layers

Decisions live in pure Swift; the system sits behind a seam

Every input enters one queue, and a pure function decides the next state and its effects, so no two events can race. The core never imports AppKit. Every macOS capability reaches it through a small protocol with one real implementation and one fake, so the whole pipeline runs in tests and in CI with no microphone.

05 · Privacy

Privacy is enforced, not just promised

No network

No networking code and no network entitlement. Apple's own model downloads are managed by the system.

enforced: privacy check fails CI on any network API

No audio on disk

Buffers stream from the mic to the analyzer and are released straight away. Nothing is written, nothing is logged.

enforced: privacy check fails CI on file I/O in the audio path

The mic is open only while you hold

Only two states open the mic, and every exit path closes it, including watchdogs for a lost key-up.

enforced: 1,000 random event sequences in a property test

No silent rewrites, by default

If the on-device model changes your words, you see a diff and accept it. Your literal transcript is always kept. Show preview = Never is an opt-in, and then Paste last gives back your own words.

enforced: tests that rejecting leaves the literal byte-identical

History is opt-in

Off by default. When on: text only, the last 50, in a private folder excluded from backups. Logs and Copy diagnostics never contain text.

enforced: storage and diagnostics tests; log privacy check in CI

08 · As built

What the implementation added

Keys

A pure decoder turns raw modifier events into press, release, chord, and cancel, using the right-hand device bit so Left Option never counts. The tap runs on its own thread and is rebuilt after sleep; a disabled tap re-reads the live key state.

Timers

Every watchdog is a deadline fixed at creation, not at first scheduling, so timeouts don't drift later under load.

Recognition

The recognizer ignores contextual strings, so Speak rescores its alternative readings: a segment takes the first alternative that spells a dictionary term the top reading misheard, within a small change (for an everyday-word term, only where the recognizer was unsure). Synthetic speech: 160 → 171 of 200 target words. Released audio is drained and padded with 300 ms of silence.

Literal step

Tidy whitespace, capitalize, apply replacement pairs (whole words, longest first, one pass), then dictionary correction: exact phrases take the term's casing (a lowercase term keeps the spoken casing); a one-edit near-miss is fixed only if the spell checker flags the word. Optional pack of ~70 tech terms.

Rewrite and preview

One guarded <cleaned> block with ratio and overlap checks (Concise may drop only fillers and lead-ins), else the literal. Polished is allowed to fix sound-alike mishearings (the on-device model rarely does) behind a keep guard: numbers, days, names, acronyms, terms, unknown words and negations must survive. Show preview: When words change (default), Always, or Never. The panel never takes focus; on a choice Speak re-activates the original app and waits up to 2 s for ⌥ to lift.

Speed

At key press in a rewrite mode, the model session is built and its instructions preloaded, so release leaves only the transcript to read. Guardrails for transforming the user's own text reply ~0.1 s sooner with the same output; the speech analyzer runs at user-initiated priority. Polished: 0.99 s → 0.58 s median. Starting the rewrite on the partial transcript at release was tried and removed (it never matched).

Delivery rescue and undo

A paste that hasn't finished in 3 s becomes a copy of the accepted text. Undo insert is offered for 30 s while the same app, field, and length still match, with focus read from the frontmost app.

History and diagnostics

Finished dictations go to a JSON-lines file (newest 50) when history is on. Release-to-result timings go to the log, and the last 20 go into Copy diagnostics with versions, permissions, and settings.
